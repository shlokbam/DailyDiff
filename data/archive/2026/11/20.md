### [Ecosystem Update] PostgreSQL 19
**PostgreSQL 19 adds powerful new maintenance and performance features.** Highlights include the REPACK command (with a CONCURRENTLY option) for reclaiming disk space without blocking reads/writes, planner‑advice extensions pg_plan_advice and pg_stash_advice, automatic scaling of I/O workers, faster foreign‑key checks, logical replication that can be enabled without a restart, read‑your‑writes consistency via the WAIT command, and parallel autovacuum of indexes with a new scoring system. The release date is 2026‑11‑19, and migration requires a dump/restore, pg_upgrade, or logical replication.

**Why it matters:** These additions cut downtime, improve query performance, and make large‑scale PostgreSQL deployments easier to manage and scale.

**Who cares:** Backend engineers, database administrators, and data platform teams that run PostgreSQL in production.

**Verdict:** `INTEGRATE` | [Source](https://www.postgresql.org/docs/release/19.0/)

### [Watchlist] Line numbers made the code I send to an LLM 42% more expensive
**Adding line numbers to code snippets inflates LLM token usage by roughly 42 %.** A measurement on the Python 3.13 standard library (131 files, 107 041 lines) showed that the typical `cat -n` format (seven‑digit number, tab, code) increased tokens from 893 573 to 1 272 868, a +42.4 % rise. Since LLM APIs charge per token, this overhead can noticeably raise costs for coding assistants that prepend line numbers for reference.

**Why it matters:** Prompt engineers and AI‑powered coding tool developers need to redesign how they reference code to avoid unnecessary token bloat and keep API bills under control.

**Who cares:** AI‑powered coding tool developers, prompt engineers, and anyone optimizing LLM usage budgets.
